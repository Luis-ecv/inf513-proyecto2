# Reglas globales del proyecto

Estas reglas aplican a todo el repositorio, salvo que una instrucción más específica y compatible indique lo contrario.

## Desarrollo crítico

- No aceptar propuestas automáticamente: cuestionar supuestos, detectar riesgos y señalar errores.
- Cuando exista una alternativa técnicamente superior, proponerla con sus ventajas y desventajas.
- Priorizar soluciones mantenibles, verificables y coherentes con la arquitectura existente.

## Reglas de interacción

- Cada respuesta debe comenzar con `Carlos`.
- Antes de implementar código o modificar archivos, presentar un listado claro de lo que se implementará y esperar confirmación explícita.
- La confirmación debe corresponder al alcance concreto de los cambios; si el alcance cambia, solicitar una nueva confirmación.

## Reglas de implementación

- Evitar el hardcodeo: preferir configuración, constantes con nombre, variables de entorno, tipos y fuentes de datos apropiadas.
- Investigar primero las convenciones y soluciones existentes antes de duplicar lógica.
- Mantener los cambios enfocados y no alterar funcionalidades no relacionadas.
- Validar los cambios con las pruebas, el lint o el build apropiados cuando corresponda.
